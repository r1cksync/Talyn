# MVP limitations

- Bedrock remains blocked; the user authorized Groq as an external LLM exception. The complete deployed synthetic workflow passed with Groq, Transcribe, Polly, S3, SQS, Rekognition, Cognito and SES simulator recipients; see acceptance. Candidate disclosure identifies external Groq processing with a versioned consent policy.
- Groq's free pilot is limited to two concurrent interviews per organization. Planning limits published for the selected model are 30 requests/minute, 8,000 tokens/minute and 200,000 tokens/day; actual account quotas apply. Large prompts fail explicitly. This is light synthetic testing capacity, not a production guarantee.
- Demo AI and typed answers are deterministic fixtures. Browser microphone/camera capture, uploads and playback are real. Fixture scores are not validated assessments of a person's ability. Production rejects demo mode.
- Ten concurrent workflows passed locally with PostgreSQL; this does not measure live AWS audio, Fargate throughput or Bedrock quotas. Single API/worker/web tasks and single-AZ RDS are development choices. Production needs multiple API/web tasks, independently sized workers, RDS Multi-AZ, autoscaling and a restore drill.
- Audio is half duplex; interruptions are unsupported. A disconnected utterance can be lost before its final Transcribe event. Partial/final captions are distinct, and low-quality or missing evidence produces insufficient evidence rather than a confident negative score.
- Video uses independent short clips and sequential playback. Stop/start boundaries may create gaps; the manifest records them. Browser failure can lose the open clip. Saved pending clips exist only in the same browser/profile; clearing site data destroys recovery. Upload recovery remains available for 24 hours after completion and cannot extend the interview timeline. Capture pauses at four pending clips; bounded upload retries and explicit resume controls retain that storage limit. Chromium was tested; Safari/Firefox need device/codec acceptance.
- Frame sampling defaults to 30 seconds. Smoothed face counts and head-pose estimates are neutral review observations. Eye direction, whole-scene tracking, person identification and sensitive appearance/voice inference are not implemented. Sampling cannot establish off-camera assistance. Observations never change competency scores and support dismissal, candidate explanation and accommodations.
- Exact quote/reference validation does not prove candidate claims or assessment fairness. No training or Kaggle data is used. Human reviewers decide; job-specific rubric validation is needed before real hiring.
- Document parsing uses a subprocess, minimal environment and Linux memory/CPU/file/time limits; embedded objects/macros are rejected. It is not a full OS sandbox against a parser exploit. A separate no-network task without AWS credentials is a production hardening option. Windows local parsing enforces timeout/size, not Linux resource limits.
- Backend tasks share a database credential and enforce tenant ownership in application code; PostgreSQL row-level security is not enabled. IAM limits AWS services/resources; authenticated backend and worker checks enforce organization object/checkpoint scope.
- SES can duplicate email across an external-service crash boundary. Sandbox/allowlists remain enabled by default. Report links require authentication; candidate feedback excludes recruiter notes and scoring guides.
- Billing, ATS integrations, a self-service manager password-recovery UI and production operational staffing are outside this MVP. Consent/accommodation/deletion features do not constitute jurisdiction-wide legal compliance certification.
